# Review App — خريطة المشروع وملاحظات الإصلاح

## خريطة الملفات

```text
review-app/
├── index.html                    # هيكل التطبيق والواجهة
├── sw.js                         # Service Worker للتخزين المحلي (same-origin فقط)
├── OneSignalSDKWorker.js         # Worker المطلوب من OneSignal Web Push
├── assets/
│   ├── css/
│   │   └── app.css               # CSS المستخرج من index.html دون حذف قواعد
│   └── js/
│       └── app.js                # JavaScript المستخرج بنفس ترتيب السكربتات الأصلي
└── docs/
    └── README_AR.md              # هذا الملف
```

## التعديلات المنفذة

1. **إصلاح migration:** تمت مطابقة `reviewDataMigrationVersion` مع الحارس `8.0-professional` حتى لا يعاد الترحيل عند كل تشغيل.
2. **إصلاح أمني في OneSignal:** أزيل استخدام REST API Key من كود المتصفح. تم الإبقاء على الاشتراك عبر OneSignal SDK، بينما الإرسال البرمجي يجب أن يتم عبر Backend آمن أو من لوحة OneSignal.
3. **Service Worker:** أصبح يخزن موارد التطبيق من نفس الأصل فقط، ولا يخزن طلبات API أو CDN الخارجية عشوائياً.
4. **ترتيب الملفات:** تم فصل CSS وJavaScript مع الحفاظ على ترتيب JavaScript الأصلي لتقليل مخاطر تغيير السلوك.
5. **الحفاظ على الوظائف:** لم تُحذف وظائف التطبيق العامة. الجزء الوحيد الذي أزيل هو إرسال OneSignal REST مباشرة من المتصفح لأنه يعرض مفتاحاً سرياً ويشكل خطراً أمنياً.

## ملاحظات تشغيل

- OneSignal Web Push يحتاج HTTPS في بيئة الإنتاج وملف `OneSignalSDKWorker.js` في جذر الموقع.
- الإشعارات المحلية عبر `Notification`/`MedianPush` لا تضمن جدولة متصفح موثوقة بعد إغلاق الصفحة؛ التطبيق يعتمد على الـnative bridge إذا كان التشغيل Native.
- Ollama وGroq ما زالا جزءاً من التطبيق كما في الأصل. مفاتيح الخدمات السحابية في المتصفح تظل حساسة؛ للاستخدام العام يفضّل وضعها خلف Backend أيضاً.


## إصلاحات إضافية — Stability / Persistence

- **Groq + OneSignal:** يتم حفظ مفتاح Groq وOneSignal App ID محلياً في IndexedDB ضمن حالة التطبيق، مع حفظ تلقائي عند تغيير الحقول. لا يتم تضمين المفاتيح الفعلية داخل ملفات المصدر.
- **OneSignal:** عند وجود App ID، يعاد تهيئة SDK والاشتراك تلقائياً عند تشغيل التطبيق إذا كانت صلاحية الإشعارات ممنوحة. إغلاق التطبيق لا يلغي صلاحية Push.
- **مهم للإشعارات بعد الإغلاق:** لا يستطيع JavaScript داخل صفحة مغلقة تشغيل `setTimeout` في الخلفية بشكل موثوق. لذلك الإشعارات التي يجب أن تصل والتطبيق مغلق تحتاج OneSignal مع إرسال/جدولة من لوحة OneSignal أو Backend آمن. الكود المحلي يبقى كـfallback عندما يكون التطبيق مفتوحاً.
- **تجميد/شاشة سوداء:** تم تقليل عمليات إعادة الرسم المتكررة عبر تجميع `renderAll()` في إطار رسم واحد، وإلغاء `backdrop-filter` و`will-change` من المسار العام الذي يسبب مشاكل GPU في بعض WebViews، مع تحسين التمرير.
- **السعة:** IndexedDB هو المخزن الرئيسي، وتم طلب `navigator.storage.persist()` وقراءة حصة التخزين. لا توجد طريقة آمنة لفرض RAM كبيرة من JavaScript؛ الذاكرة الفعلية يحددها الجهاز والنظام.
